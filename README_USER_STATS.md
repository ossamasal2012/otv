# 👥 ميزة عدّاد المستخدمين + المستخدمين النشطين الآن (مباشر / Real-time)

## الفكرة باختصار
خانتان تظهران داخل التطبيق (شريط مضغوط دائم أعلى قائمة القنوات، وبطاقتان تفصيليتان داخل شاشة
**⚙️ الإعدادات**):

| الخانة | تعني ماذا بالضبط | التقنية |
|---|---|---|
| 👥 **إجمالي المستخدمين** | عدد **الأجهزة الفريدة** التي التطبيق مثبّت عليها حالياً | Firebase Realtime Database |
| 🟢 **نشطون الآن** | عدد الأجهزة التي التطبيق **مفتوح ومعروض على الشاشة فعلياً** بهذه اللحظة | Cloudflare Worker + Workers KV |

**كلتا الخدمتين مجانيتان بالكامل ولا تحتاجان أي بطاقة دفع إطلاقاً** — هذا كان شرطاً أساسياً
بالتصميم، وسنشرح لماذا بالتفصيل أدناه.

---

## لماذا تصميم هجين (خدمتان لا خدمة واحدة)؟

جربنا بدايةً استخدام Firebase وحده للميزتين معاً، لكن تبيّن وجود قيد مهم: خطة Firebase
المجانية (Spark) تسمح بـ **100 اتصال متزامن فقط** بقاعدة البيانات. "إجمالي المستخدمين" لا
يتأثر بهذا القيد إطلاقاً (مجرد رقم يُقرأ/يُكتب عرضياً، لا يحتاج اتصالاً دائماً). لكن حساب "نشط
الآن" بدقة لحظية (مع اكتشاف تلقائي للخروج المفاجئ) يتطلب إبقاء اتصال مفتوح طوال فترة استخدام كل
شخص للتطبيق — فلو تجاوز عدد المستخدمين المتزامنين 100 شخص بنفس اللحظة (متوقع جداً بتطبيق رياضي
وقت المباريات)، الزائد عن 100 تُرفض اتصالاته.

الحل: أبقينا **"إجمالي المستخدمين" على Firebase** (لا مشكلة هناك إطلاقاً، بلا حدود)، ونقلنا
**"نشط الآن" لـ Cloudflare Worker** الذي يعمل بأسلوب مختلف تماماً — "نبضات" HTTP قصيرة دورية
بدل اتصال دائم — فلا يوجد أي سقف "اتصالات متزامنة" فيه من الأساس. الأهم: **Cloudflare Workers
المجانية لا تطلب بطاقة دفع إطلاقاً**، حتى كإجراء شكلي — عكس ترقية Firebase لخطة Blaze.

## كيف تحقق الدقة المطلوبة بالضبط

### 1) "إجمالي المستخدمين" لا يزيد عند التحديث، ولا يتكرر عند إعادة التثبيت
كل جهاز له هوية ثابتة (`deviceId`) مبنية على `ANDROID_ID` — قيمة موثّقة رسمياً من گوگل بأنها
تبقى كما هي عند تحديث التطبيق، وحتى عند حذفه وإعادة تثبيته من جديد على نفس الجهاز (طالما لم
يُعاد ضبط المصنع، ولم يتغيّر توقيع التطبيق — وأنتم توقّعون دائماً بنفس المفتاح، فهذا الشرط محقّق
تلقائياً). تتغيّر هذه القيمة فقط عند إعادة ضبط المصنع، وعندها فعلياً يُعتبر "جهازاً جديداً"
بمنطق سليم.

آلية الحساب نفسها لا تحتمل الخطأ رياضياً: أول ظهور لأي `deviceId` على الخادم يمر عبر عملية
ذرّية (Transaction) تزيد العدّاد الإجمالي بمقدار 1 بالضبط **فقط** إذا لم يكن الجهاز مسجّلاً من
قبل — مطبّق بقواعد أمان قاعدة البيانات نفسها (`database.rules.json`) وليس فقط بكود التطبيق.

### 2) "نشطون الآن" دقيق ومتجدد ذاتياً
كل جهاز يرسل "نبضة" HTTP صغيرة كل 30 ثانية طالما التطبيق مفتوح أمام المستخدم فعلاً (نراقب هذا
عبر `ProcessLifecycleOwner` على مستوى التطبيق كله، فلا يتأثر بدوران الشاشة أو التنقل الداخلي).
كل نبضة تُسجَّل بـ Cloudflare KV بصلاحية 70 ثانية فقط.

- عند خروج طبيعي (رجوع للشاشة الرئيسية) → نرسل إشعار "مغادرة" فوري، فيختفي الجهاز من العدّاد
  على الفور.
- عند خروج غير طبيعي (تعطّل التطبيق، إغلاق قسري من النظام، انقطاع إنترنت مفاجئ) → لا يصل أي
  إشعار مغادرة، لكن صلاحية آخر نبضة تنتهي تلقائياً خلال أقل من 70 ثانية، فيختفي الجهاز من العدّاد
  بنفسه دون أي كود إضافي يراقب "الانقطاع" — يعادل تماماً ما توفره أنظمة الحضور الاحترافية.
- العدّاد يصحّح نفسه بنفسه باستمرار: كل عدة ثوانٍ تُعاد مطابقته مع المفاتيح الحيّة فعلياً فقط
  (المنتهية تُستبعد تلقائياً)، فلا يتراكم أي انحراف بمرور الوقت مهما طال تشغيل الخدمة.

## خطوات التفعيل (تُسوّى مرة واحدة فقط، بدون أي بطاقة دفع)

### الجزء الأول: إجمالي المستخدمين (Firebase — كما كان)

1. [Firebase Console](https://console.firebase.google.com/) → مشروع **yallagoal-40ec3** →
   **Build → Realtime Database → Create Database** (اختر أقرب موقع خادم، ووضع Locked mode).
2. تبويب **Rules** بنفس الصفحة → الصق محتوى `database.rules.json` كاملاً → **Publish**.
3. **⚙️ Project settings → عام → Download google-services.json** → استبدل به
   `app/google-services.json` بالمستودع → Commit.

*(هذا الجزء لا يحتاج أي بطاقة دفع؛ خطة Spark المجانية تكفي بلا حدود لهذا الاستخدام.)*

### الجزء الثاني: المستخدمون النشطون الآن (Cloudflare Worker — جديد)

1. أنشئ حساب Cloudflare مجاني (لو ما عندك) على [dash.cloudflare.com](https://dash.cloudflare.com)
   — بريد إلكتروني فقط، **بدون أي بطاقة دفع**.
2. ثبّت أداة Wrangler محلياً على جهازك (تحتاج Node.js مثبتاً):
   ```bash
   npm install -g wrangler
   wrangler login
   ```
   (سيفتح المتصفح لتسجيل الدخول بحساب Cloudflare — خطوة لمرة واحدة.)
3. من داخل مجلد `cloudflare-worker/` بهذا المستودع:
   ```bash
   cd cloudflare-worker
   wrangler kv namespace create PRESENCE
   ```
   سيطبع الأمر شيئاً شبيهاً بـ:
   ```
   id = "abcd1234..."
   ```
   انسخ قيمة `id` والصقها مكان `REPLACE_WITH_KV_NAMESPACE_ID` بملف `wrangler.toml`.
4. عيّن سراً مشتركاً (كلمة سر طويلة عشوائية تحميك من إساءة الاستخدام العلني للرابط):
   ```bash
   wrangler secret put YG_SHARED_SECRET
   ```
   سيطلب منك كتابة القيمة — اكتب نصاً عشوائياً طويلاً (30+ حرف)، واحتفظ بنسخة منه، ستحتاجه
   بالخطوة التالية.
5. انشر الـ Worker:
   ```bash
   wrangler deploy
   ```
   سيطبع رابطاً شبيهاً بـ: `https://yallagoal-active-users.<اسمك-الفرعي>.workers.dev`
6. افتح `app/src/main/java/com/yallagoal/app/UserStatsManager.java` وعدّل هذين الثابتين
   بأعلى الملف (ابحث عن `REPLACE_ME`):
   ```java
   private static final String ACTIVE_STATS_BASE_URL = "الرابط الذي طبعه wrangler deploy";
   private static final String ACTIVE_STATS_SHARED_SECRET = "نفس القيمة التي كتبتها بالخطوة 4";
   ```
7. ابنِ التطبيق ووزّعه بنفس آلية الإصدار المعتادة عندكم.

> **قبل تنفيذ هذه الخطوات:** الخانة الأولى (إجمالي المستخدمين) تعمل بمجرد إتمام الجزء الأول،
> بينما خانة "نشط الآن" تبقى بهدوء على "0" (لا تُسبب أي خطأ أو تعطّل) حتى تُنفّذ الجزء الثاني.

## أين تظهر الأرقام بالضبط؟
- **شريط مضغوط دائم** أعلى قائمة القنوات (يظهر فوراً بعد الدخول بالرمز السري).
- **بطاقتان تفصيليتان أكبر** داخل شاشة **⚙️ الإعدادات**.

كلاهما يتحدث لحظياً بدون أي إجراء من المستخدم.

## اختبار سريع بعد التفعيل
1. ثبّت التطبيق على جهازين مختلفين وسجّل الدخول بالرمز السري بكل منهما. "إجمالي المستخدمين"
   يجب أن يصبح 2.
2. أبقِ أحدهما مفتوحاً بالمقدمة، وأرسل الآخر للخلفية (اضغط الشاشة الرئيسية). خلال ثوانٍ معدودة
   "نشطون الآن" يجب أن يصبح 1 على كلا الجهازين (الرقم مشترك للجميع).
3. أغلق التطبيق تماماً من الجهازين (لا يكفي إرساله للخلفية — أوقفه من "التطبيقات الحديثة") ثم
   انتظر دقيقة تقريباً. "نشطون الآن" يجب أن يعود لـ 0.
4. حدّث التطبيق بأحد الجهازين (بدون حذفه) — "إجمالي المستخدمين" يجب أن يبقى كما هو بلا زيادة.
5. احذف التطبيق من أحد الجهازين ثم أعد تثبيته وسجّل الدخول من جديد — "إجمالي المستخدمين" يجب أن
   يبقى كما هو أيضاً.

## سقف الاستخدام المجاني — بصدق تام وبالأرقام الحقيقية

خطة Cloudflare Workers المجانية: **100,000 طلب/يوم**. هذا سقف **حجم** (كم طلب باليوم كله)،
مختلف تماماً عن سقف "الاتصالات المتزامنة" بفايربيس. بمعدل نبضة كل 30 ثانية لكل جهاز نشط:

- كل مستخدم يشاهد لمدة ساعتين (مباراة كاملة مثلاً) يُرسل ~240 نبضة.
- يعني الحصة المجانية اليومية (100,000 نبضة) تكفي تقريباً لـ **~400 مستخدم متزامن** خلال مباراة
  واحدة بذلك اليوم (أو أكثر لو تفرّق الاستخدام على مباريات/أوقات مختلفة بنفس اليوم).

هذا أفضل بكثير من سقف Firebase الصارم (100 فقط، دائماً)، لكنه **ليس غير محدود فعلياً** لو صار
عندكم آلاف المشاهدين المتزامنين بمباراة كبيرة جداً. عند تجاوز الحصة اليومية، الأثر الوحيد: خانة
"نشط الآن" تتوقف عن التحديث مؤقتاً لبقية ذلك اليوم فقط (تعود تلقائياً بعد منتصف الليل UTC) —
**لا يتأثر تشغيل القنوات أو البث إطلاقاً**، لأنه لا علاقة له بهذه الخدمة نهائياً.

### لو احتجتم رفع هذا السقف مستقبلاً
- **تقليل تكرار النبضة**: غيّر `HEARTBEAT_INTERVAL_MS` بملف `UserStatsManager.java` من 30
  ثانية لقيمة أكبر (مثلاً 60) — يخفّض الحمل للنصف تقريباً، مقابل دقة أقل قليلاً (تأخر يصل حتى
  دقيقة تقريباً بدل نصف دقيقة تقريباً).
- **خطة Cloudflare المدفوعة**: 5$/شهر فقط، وترفع السقف اليومي كثيراً — لكن هذه تحتاج بطاقة دفع
  بالطبع، فاذكرناها فقط كخيار مستقبلي، لسنا نطبّقها الآن حسب طلبك.

## ملخص سريع (للرجوع مستقبلاً)
```
Firebase (إجمالي المستخدمين):
1. Realtime Database → Create Database
2. Rules → الصق database.rules.json → Publish
3. حمّل google-services.json محدّث → استبدل بالمستودع

Cloudflare (نشط الآن):
1. npm install -g wrangler && wrangler login
2. cd cloudflare-worker && wrangler kv namespace create PRESENCE
   → انسخ الـ id إلى wrangler.toml
3. wrangler secret put YG_SHARED_SECRET
4. wrangler deploy
   → انسخ الرابط + السر إلى UserStatsManager.java (ثابتَي ACTIVE_STATS_*)
```
