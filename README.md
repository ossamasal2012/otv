# دليل إصدار تحديث جديد لتطبيق يلا گول

## الفكرة باختصار
كل مرة يفتح فيها أي مستخدم التطبيق، يتحقق تلقائياً من رقم إصدار موجود بملف اسمه `version.json` على الإنترنت. إذا كان الرقم فيه أكبر من رقم النسخة المثبتة عند المستخدم، تطلع له رسالة تحديث إلزامية. بمجرد ما يحدّث، رقم نسخته يصير مطابق، فالرسالة تختفي ولا ترجع تطلع إلا لما تصدر نسخة أحدث من هذا الرقم.

**أنت ما تلمس ملف `version.json` يدوياً أبداً** — يتولد تلقائياً بكل مرة تبني فيها التطبيق، بالاعتماد على رقمين تحددهم انت بملف واحد بس.

---

## الخطوات (تسويها كل مرة تبي تصدر تحديث)

### الخطوة 1: افتح ملف `app/build.gradle` بمستودعك
روح لمستودعك على GitHub → ادخل لمجلد `app` → افتح ملف `build.gradle` (تأكد إنه اللي داخل مجلد app، مو اللي بالجذر).

### الخطوة 2: زِد رقمين اثنين فقط
دوّر على هذا الجزء بالأعلى:

```groovy
defaultConfig {
    applicationId "com.yallagoal.app"
    minSdk 23
    targetSdk 34
    versionCode 1
    versionName "1.0"
}
```

غيّرهم بهالشكل:

| الحقل | شنو تسوي فيه | مثال |
|---|---|---|
| `versionCode` | **زده رقم واحد بالضبط** عن آخر مرة (لازم يكبر دائماً، ما ينرجع أبداً) | من `1` إلى `2` |
| `versionName` | غيّره لأي نص يوضح النسخة للمستخدم (شكله حر تماماً) | من `"1.0"` إلى `"1.1"` |

مثال بعد التعديل:
```groovy
defaultConfig {
    applicationId "com.yallagoal.app"
    minSdk 23
    targetSdk 34
    versionCode 2
    versionName "1.1"
}
```

⚠️ **الأهم:** `versionCode` هو الرقم اللي يعتمد عليه نظام التحديث بالكامل ليقارن. لازم يكبر بكل إصدار (2 ثم 3 ثم 4...) وإلا التحديث ما راح يشتغل أو يتكرر بشكل خاطئ.

### الخطوة 3: احفظ التعديل (Commit)
اضغط **Commit changes** بأسفل صفحة التعديل على GitHub.

### الخطوة 4: (تلقائي) البناء يبدأ لحاله
بمجرد الحفظ، الـ workflow يشتغل تلقائياً ويسوي كل هذا بدون أي تدخل منك:
1. يبني نسخة release موقّعة من التطبيق بالكود الجديد.
2. يولّد ملف `version.json` جديد فيه رقم `versionCode`/`versionName` اللي حطيته بالضبط.
3. ينشر ملف APK + `version.json` كـ "Release" جديد بالمستودع باسم `latest` (يستبدل النسخة السابقة تلقائياً).

تقدر تتابعه من تبويب **Actions** لين تشوف العلامة الخضراء ✅.

### الخطوة 5: (اختياري) تحقق يدوياً
بعد ما يخلص البناء، روح لصفحة **Releases** بمستودعك (تظهر بالصفحة الرئيسية جنب "About")، وتأكد إن أحدث نسخة فيها ملفين: `app-release.apk` و `version.json`. اضغط على `version.json` وشوف محتواه للتأكد إن الرقم مطابق لللي كتبته.

## شنو يصير عند المستخدم؟

1. المستخدم يفتح التطبيق (أي وقت، حتى لو كان مثبت من زمان).
2. التطبيق يتحقق من `version.json` بالخلفية (يحتاج إنترنت).
3. إذا لقى رقم أكبر من نسخته المثبتة → تطلع رسالة "تحديث متوفر" **ما تنقفل** إلا بالضغط على "تحديث الآن".
4. يضغط "تحديث الآن" → يبدأ تحميل ملف APK تلقائياً (يشوفه بشريط الإشعارات مثل أي تحميل).
5. بعد اكتمال التحميل → تفتح شاشة التثبيت تلقائياً.
6. بعد التثبيت، يفتح التطبيق يدوياً → رقم نسخته الحين يصير مطابق لآخر إصدار → الرسالة **ما تطلع مرة ثانية** إلا إذا صدرت نسخة أحدث بالمستقبل.

## نصائح مهمة

### لا تنسَ رفع الرقم كل مرة
لو نسيت تزيد `versionCode` وعدّلت بس بالكود (مثلاً أصلحت خطأ أو زدت ميزة) وبنيت من جديد، **التحديث ما راح يوصل لأي مستخدم**، لأن النظام يقارن بالأرقام بس، مو بالمحتوى.

### تجربة سريعة قبل ما توزع رسمياً
إذا تبي تتأكد إن رسالة التحديث تطلع صح قبل ما توزعها للجميع:
1. ثبّت بجهازك نسخة برقم `versionCode` قديم (مثلاً 1).
2. اصدر تحديث برقم `versionCode` أعلى (مثلاً 2) باتباع الخطوات فوق.
3. افتح التطبيق بجهازك (النسخة القديمة) وشوف هل تطلع الرسالة صح.

### إذا احتجت توقف "الإلزامية" لتحديث معين
بالكود الحالي، كل التحديثات إلزامية دائماً (`force_update: true` مبرمج ثابت). إذا حبيت مستقبلاً تسوي تحديثات اختيارية (فيها زر "لاحقاً")، خبرني وأعدّل الكود يخليك تتحكم فيها.

### تغيير نص رسالة التحديث
النص الحالي المولّد تلقائياً هو:
> "يتوفر إصدار جديد من تطبيق يلا گول (الإصدار X.X). يرجى التحديث للمتابعة."

إذا تبي نص مختلف لكل تحديث (مثلاً تشرح شنو الجديد بالتحديث)، خبرني وأضيف لك خطوة بسيطة تكتب فيها النص بنفسك وقت كل إصدار.

## ملخص سريع (للرجوع السريع مستقبلاً)

```
1. افتح app/build.gradle
2. زد versionCode بواحد
3. غيّر versionName
4. Commit changes
5. انتظر Actions يخلص (علامة خضراء)
6. خلص — كل المستخدمين رح تطلعلهم رسالة التحديث تلقائياً
```
